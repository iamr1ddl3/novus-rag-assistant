Ask a banking policy question, get a grounded answer with sources

Novus Bank is a fictional Indian neo-bank. This app answers questions over its 19 policy documents (accounts, cards, loans, UPI, fraud, KYC and more). Every answer is built only from retrieved passages, cites its source, abstains when unsure, and is traced in Langfuse.

The three phases

Once

1. Ingest

corpus/*.md → ingest.py splits into 500-char chunks → embeds with text-embedding-3-small (1536-d) → stores in Postgres + pgvector.

Per question

2. Answer

POST /query → rag.ask(): guardrail → PII redaction → embed → retrieve → generate with confidence → answer + sources + trace_id.

After changes

3. Evaluate

eval_harness.py scores 72 golden queries; check_regression.py fails CI if any metric drops more than 5 points.

Dense vs Hybrid, with a query that shows the difference

Dense search matches meaning; keyword search matches exact words. Hybrid runs both and merges the rankings, so a rare term like "Form 60" still finds its document.

Dense default

Embeds the question and finds the 5 nearest chunks by cosine similarity (pgvector HNSW).

Strong at: paraphrases. "How much can I send by UPI in a day?" finds the "Per day ₹1,00,000" row even without the word "limit".

Weak at: short codes and names. "Form 60" has little meaning to an embedding, so the right chunk can rank below generic KYC text.

Hybrid dense + BM25

Takes the top 10 from each side, then merges with Reciprocal Rank Fusion:

score(chunk) = 1/(60 + rank_dense) + 1/(60 + rank_bm25)

A chunk ranked well by either method rises. BM25 sees the literal token "60" next to "Form" and pulls up 13_kyc_and_compliance.

Safety: what stops a bad answer

Banking answers must be right or not given. Four layers, each optional and each traced.

1. Input guardrail opt-in

Topic + safety check before any retrieval or LLM call. Blocks prompt injection, off-topic and unsafe requests and returns a refusal immediately (retrieval_mode = "blocked").

2. PII redaction on by default

Microsoft Presidio + spaCy (en_core_web_lg) replaces names, phone numbers, PAN, account numbers with typed placeholders before embedding, BM25 and the LLM. Placeholders are restored in the final answer.

"My PAN is ABCDE1234F" → "My PAN is <IN_PAN>"

3. Confidence gate on by default

The model answers with a structured confidence (high / medium / low) and a reason. Low → the answer is replaced with a handoff message and a SupportTicket is created. A cosine-similarity floor was tried first and rejected: out-of-corpus questions scored higher than real ones on this corpus.

4. Output guardrail opt-in

Checks the answer against the retrieved context for hallucination. If it fails, regenerates once with a stricter prompt; if that fails too, returns a safe fallback. Adds about 1.7 s per query, so it is sampleable (guardrail_sample_rate).

Known gap: the no-answer refusal pass-rate is about 50%. The model still answers some banking questions that aren't in the corpus. Injection, adversarial and off-topic cases pass 100%.

How well it works (measured, not claimed)

72-query golden set: 57 answerable + 15 should-not-answer. Faithfulness and correctness are LLM-judge scores (gpt-4o-mini, temperature 0), normalized to 0–1.

Regression gate in CI

Every PR runs eval_harness.py then check_regression.py. If any metric drops more than 5 points below baseline_scores.json, the check fails.

With only 15 refusal cases, one changed judgment moves that metric by 6.7 points. That's why one PR on 2026-11-22 failed with no code change (13/15 → 12/15) and passed on re-run.

Known weaknesses (by design, measured)
  1. Boundary splits: 500-char chunks with no overlap cut some answers in half.
  2. Table rows: a tier's number can land in a different chunk from its header.
  3. Multi-hop: one retrieval pass, so two-document questions struggle.
  4. Vocabulary overlap: "grace period" appears in 3 policies.
  5. Old docs: the corpus still holds legacy Acmera shop docs that can leak into "membership" answers.

Every question is a trace in Langfuse

Each stage is decorated with @observe, so one question produces one trace with a span per step. Click a span. Since 2026-11-22 the app uses the Langfuse v5 SDK (OpenTelemetry), after Langfuse Cloud shut down its old API.

ask

The root span: one per question. Its input is the question and its output the answer; the API returns its id as trace_id.

Where: project novus-support-agent on us.cloud.langfuse.com. The support agent reports to the same project, and its policy lookups show up here as extra ask traces in Hybrid mode.
